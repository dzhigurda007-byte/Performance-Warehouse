# Performance Warehouse

Адресный складской учёт ТМЦ: **Склад → Стеллаж → Ячейка → (Короб) → Товар**, QR-маркировка,
приходные и расходные ордера, выдача ТМЦ сотрудникам под ответственность.

## Режимы работы

| Режим | Где база | Кто работает |
|---|---|---|
| **Сервер склада (ПК)** | на ПК с Windows (`PerformanceWarehouse-Setup.exe`) | телефоны и ТСД по Wi-Fi + рабочее место в браузере на ПК |
| **Автономно** | на самом телефоне | один человек |

Сборки (установщик для Windows, APK и портативный архив) публикуются на странице **Releases** при каждом изменении кода.
Инструкция по установке сервера — `windows/README.txt` (лежит и внутри архива).

## PerformanceWarehouseLite

Отдельное упрощённое приложение для одного телефона (`PerformanceWarehouseLite.apk`, пакет
`com.performance.warehouse.lite` — ставится рядом с полной версией). Без сервера, без регистрации,
один пользователь — администратор. База — только в телефоне.

* номенклатура: артикул, наименование, SPP номер, штрихкод, количество на складе;
* ячейки хранения (есть всегда «ОСН» — основная), QR-этикетки ячеек, перемещение между ячейками;
* приходные и расходные ордера: сканер (1 скан = 1 шт. или с вводом количества) или вручную,
  новый ШК при приходе — сразу карточка товара; расход сверх остатка не проводится;
* «Поделиться (PDF)» — ордер уходит PDF-файлом в мессенджер или на почту;
* история движений с фильтрами по номенклатуре, ячейке, дате и количеству;
* резервная копия базы (JSON-файл) — отправить себе и восстановить на другом телефоне.

Код — `src/lite/` (ядро `src/lite/core`, экраны `src/lite/app`), сборка — `APP_VARIANT=lite`
(см. `app.config.js`): `APP_VARIANT=lite npx expo start`.

## Роли и иерархия

Администратор → Руководитель → Кладовщик → Сотрудник → Разнорабочий; отделы с главой и
непосредственные руководители.

| Роль | Права |
|---|---|
| Администратор | всё: настройки, отделы, роли, приглашения |
| Руководитель | полный функционал склада, рассылает ссылки-приглашения |
| Кладовщик | полный функционал склада, выдаёт ТМЦ нижестоящим; приглашать не может |
| Сотрудник | может брать ТМЦ со склада на себя |
| Разнорабочий | ничего не берёт сам; получает ТМЦ от кладовщика и возвращает их |

Новые сотрудники подключаются по **ссылке-приглашению** (роль, отдел и руководитель задаются заранее).

## Возможности

- **Номенклатура** — справочник наименований (как в 1С) с группами и подгруппами; загрузка из
  Excel (`артикул | Название | ШК`). Физический товар хранится в ячейках **партиями с датой приёмки**.
- **Приходный ордер** — по факту со сканера ТСД/телефона (несколько штук по одному ШК, быстрый режим
  «скан = +1») или из Excel (`артикул | Название | ШК | Количество`). Без указания места товар
  падает в **буферную ячейку** склада.
- **Перемещение** — весь товар или часть по одному ШК; дата приёмки сохраняется. Перемещение коробов.
- **Расходный ордер** (по заявке с FIFO-подбором мест или по факту сканированием) проводится двумя способами:
  - **Списать** — товар уходит из базы, в истории: что, откуда, когда, кто;
  - **Выдать** — товар передаётся под ответственность одному или нескольким людям
    (10 лопат и 10 пар перчаток → 10 разнорабочим, кнопка «Поровну»); у каждой выдачи свой инвентарный QR.
- **Выдачи** — личный кабинет: «Мои ТМЦ», «Выдано мной» (кому, что, сколько, когда), «Команда» для руководителя.
- **Возврат** — оформляет получатель или выдавший; отметка из списка (Без повреждений, Грязное,
  Требует ремонта, Сломано окончательно, Утеряно) и комментарий. Когда вернули всё — автоматически
  формируется приходный ордер; провести его может выдавший или его руководитель.
- Выдача ТМЦ включается администратором в настройках.
- Печать ордеров (лист подбора) и QR-этикеток ячеек, коробов, товаров и инвентарных номеров.

## Разработка

```bash
npm install
npm run typecheck          # TypeScript: приложение, тесты, сервер
npm test                   # бизнес-логика и сервер на реальном SQLite
npm run web:build          # веб-версия (рабочее место на ПК) → dist-web/
npm run server:start       # собрать и запустить сервер с веб-версией на :8080
npx expo start             # приложение для телефона
```

## Структура

```
src/core/      общее ядро бизнес-логики (работает и на телефоне, и на сервере)
  services/    склад, номенклатура, остатки, документы, выдачи, пользователи, история
  api.ts       полный список операций (вызываются напрямую или через POST /api/rpc)
src/app/       экраны (Expo Router)
src/lib/       подключение к серверу / локальной базе, Excel, печать
src/lite/      PerformanceWarehouseLite (APP_VARIANT=lite): своё ядро, экраны, резервная копия
server/        локальный сервер склада (Node.js + SQLite)
windows/       запуск сервера на Windows, автозапуск, брандмауэр, инструкция
tests/         node:test
docs/          архитектура и предложение по доработке
```
